# 当前产品行为与验收说明

## 产品目标

LaunchScope 帮助不了解 macOS 启动机制的用户看懂并管理自启动项目。主流程只有四步：

1. 发现系统设置没有完整展示的自启动项目；
2. 看懂加入方式、启动原因、时间证据和实际运行内容；
3. 停止不需要的自启动；
4. 在操作记录中恢复。

它不是恶意软件扫描器、系统性能监控器或通用审计报告工具。

## 信息架构

- “自启动项目”默认只列第三方与自定义项目。
- “自启动来源”包含用户/全局 LaunchAgent、LaunchDaemon、后台项目、登录项与 Homebrew 服务。
- Cron 和 Shell 初始化命令单独放在“相关自动任务”，因为它们不一定在 macOS 开机或图形登录时执行。
- Apple 系统 LaunchAgent 与 LaunchDaemon 不进入主导航。
- 主工具栏只保留操作记录与恢复、显示选项、重新扫描、更新系统后台项目和搜索。

## 列表与归组

- 同一 Homebrew 服务在 Homebrew、launchd 和后台记录中的条目归为一个项目。
- Homebrew 状态记录优先作为代表项，同时合并 launchd plist 中的命令、参数、环境变量和启动条件。
- 有可靠 Bundle ID 或应用路径时按所属应用归组。
- 无法归因的项目各自展示，不得把所有“未归因项目”视为同一应用。
- 分组只表达多条来源记录，不把启发式名称匹配描述为绝对归属。

## 详情

详情页按以下顺序展示：

1. 为什么会自动启动：加入方式、原因、启动时机和判断依据；
2. 停止或恢复入口；
3. 什么时候出现：配置创建时间、最后修改时间、首次发现时间；
4. 同一项目的其他来源记录；
5. 实际运行内容：执行文件、参数、工作目录、触发条件和环境变量；
6. 当前运行状态、来源、签名与折叠的完整原始配置。

时间文案必须区分：

- 配置创建/修改时间来自文件系统，可能被升级或重新安装改变；
- 首次发现时间来自 LaunchScope 保存的扫描快照，不等于安装时间；
- 无法从现有文件确定具体创建者或精确原因时，不得猜测。

敏感环境变量默认遮挡。搜索可以匹配名称、标识、路径和启动参数。

## 状态模型

界面分别展示配置是否启用、launchd 是否加载、进程是否运行、执行目标是否存在。
这些状态不能压缩成一个开关。

## 可恢复控制

- 当前用户 LaunchAgent 和无 sudo 的 Homebrew 服务提供“停止自启动”和“恢复自启动”。
- 停止 LaunchAgent 时只修改 launchd 允许状态并卸载任务，不删除或改写 plist。
- Homebrew 操作调用 brew services stop 或 start，不手工修改其生成的配置。
- 每次操作前二次确认，操作后自动重新扫描。
- 操作记录与恢复入口保留最近操作和当前可恢复项目。
- 全局 LaunchAgent、LaunchDaemon、Cron 和 Shell 当前只读。

## 扫描与隐私

- 单个来源失败必须生成 ScanIssue，其他来源继续扫描。
- 系统后台记录只在用户主动更新时调用 sfltool，并设置短超时。
- 令牌、密码和密钥等敏感环境变量默认遮挡。
- 后台扫描不探测 Documents、Desktop、Downloads 和 iCloud Drive。

## 应用内更新

- 发现新版本时同时展示当前版本与目标版本。
- 下载阶段展示“正在下载 LaunchScope x.y.z”和实际进度，下载与安装不得合并成一个模糊状态。
- 下载完成后先核对 SHA-256、Bundle ID、版本、代码签名和签名身份连续性，再允许应用退出。
- 安装程序必须独立于当前进程运行；当前应用退出后才能备份并替换 `.app`，不得互相等待。
- 替换失败或安装后校验失败时恢复原版本，并在下次启动显示失败原因。

## 验证

修改后统一执行 mise run check。界面验收应确认用户无需打开审计工具，
即可找到启动原因、时间证据、实际参数以及停止和恢复入口。
