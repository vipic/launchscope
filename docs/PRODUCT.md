# 产品与验收说明

## 产品目标

用户不需要知道启动项位于哪个目录或使用哪条命令。LaunchScope 以“所属应用/自定义命令”为中心归组，同时保留底层证据，支持从概览逐层展开到原始配置。

## 状态模型

界面分别显示以下状态，不能压缩为单个开关：

1. 配置是否存在；
2. 配置是否标记启用；
3. launchd 是否加载；
4. 进程是否正在运行；
5. 执行目标是否仍然存在。

## 首版验收场景

- 首次打开自动扫描，扫描期间窗口可以交互且显示进度。
- 默认进入“第三方与自定义”，Apple 系统项不干扰主要列表。
- 关闭“隐藏 Apple 项目”并进入“全部项目”后可查看系统项。
- 点击项目后可查看来源路径、执行文件、参数、启动条件、签名和原始 plist 字段。
- `KeepAlive` 字典、日历计划、环境变量等复杂值不会导致解析崩溃。
- 执行文件已删除时显示“目标已缺失”。
- BTM、Homebrew 或 crontab 不可用时其他来源仍正常展示，并在“扫描提示”解释原因。
- 搜索可以匹配应用名、Label、Bundle ID、Team ID、路径和参数。
- 敏感环境变量默认显示为圆点，用户明确开启后才显示原值。
- 详情页按来源显示处置建议；登录项可跳转系统设置，文件型来源可在 Finder 中定位。
- 只读诊断命令会正确转义动态参数，复制命令不会自动执行。

## 后续候选

- 可恢复停用、配置备份与回滚
- 资源占用与启动耗时观察

## 第二阶段：可恢复控制

- 仅允许操作当前用户 `~/Library/LaunchAgents` 目录中的非 Apple 项目。
- 停用执行 launchd `disable` 与 `bootout`，恢复执行 `enable` 与 `bootstrap`。
- 不删除、移动或改写原始 plist；每次操作前二次确认，操作后自动重新扫描。
- `print-disabled` 的 override 状态与 Loaded、Running 分开显示，不能因停用而掩盖仍在运行的进程。
- 该阶段暂不直接操作全局 Agent、Daemon、系统项目、Homebrew、Cron、Shell 与后台任务。

## 第三阶段：Homebrew 服务控制

- 只操作无 `sudo` 的当前用户 Homebrew 服务，不管理 root LaunchDaemon。
- 运行中的服务可执行 `brew services stop`，停止并取消登录启动；停止状态可执行 `brew services start` 恢复。
- 服务名必须来自扫描结果并通过保守格式校验；命令使用参数数组执行，不经过 shell。
- 操作前二次确认，命令设置 15 秒超时并捕获 stderr，操作后自动重新扫描。

## 第四阶段：操作历史与撤销

- 在 Application Support 中最多保存 100 条 JSON 历史，写入使用原子替换。
- 历史只包含稳定项目标识、显示名、来源、动作、前后状态、结果和时间；不得保存路径、参数、环境变量或原始配置。
- 仅允许撤销该项目最新、成功且未撤销的操作，并要求当前扫描状态对应的可用动作与反向动作一致。
- 撤销仍需经过原控制器的目录、UID、来源、服务名与权限边界校验，完成后重新扫描并生成新的历史记录。
- 历史读取或保存失败必须在界面提示，不能静默丢失。

## 第五阶段：扫描差异

- 每次完成扫描后，以 SHA-256 处理后的稳定项目 ID 保存一份脱敏快照，并与上一次完成扫描比较。
- 快照只保留 label、安全显示名、来源、允许状态、运行状态、目标存在性、签名类型和 Apple 归属。
- 不保存路径、参数、环境变量、Cron 命令或原始配置；首次扫描只建立基线。
- 变化分为新增、移除与状态变化；状态变化明确列出名称、允许、运行、目标、签名或 Apple 归属字段。
- 快照读取或保存失败必须在扫描变化界面提示，写入使用原子替换。

## 第六阶段：报告、信任与提醒

- JSON 可包含项目、脱敏问题摘要与最近变化；CSV 提供项目表。导出前必须展示字段预览并可选择当前筛选或全部项目。
- 默认排除路径、参数、环境变量、原始配置、PID、证书链与用户备注；只有用户明确勾选时 JSON 才包含备注。
- 备注、标签和信任状态以来源与标识组成的脱敏稳定键持久化，不保存启动路径和配置内容。
- 提供未信任筛选与隐藏已信任项目选项；相邻扫描中新出现且未信任的第三方项目需要明显标记。
- 系统通知默认关闭，用户主动开启时才请求权限；相同扫描变化使用持久化脱敏键去重，避免重复提醒。

## 第七阶段：Cron 与 Shell 安全停用

- Cron 支持普通五段表达式和 `@reboot` 等宏规则；操作时重新读取完整 crontab，并同时校验完整内容指纹、行号和原文。
- 停用以包含原文的 LaunchScope 专用注释替换目标行，恢复只识别完全匹配的专用标记；不删除命令或脚本。
- Shell 配置按有效行展示和操作，仅允许当前用户主目录下既有允许列表中的普通文件，并保留原权限。
- Shell 文件存在控制结构、续行或 heredoc 时整份文件保持只读；符号链接、所有权异常、非 UTF-8 或扫描后内容变化时拒绝修改。
- 所有操作继续进入脱敏操作历史，执行后自动重新扫描；安全撤销沿用相同的路径、指纹与原文校验。

## 发布前控制验收

- 二次确认必须显示 Cron/Shell 的目标来源和行号，不显示控制元数据中的原始行或指纹。
- 验收覆盖专用标记往返、空行与缩进保留、错误行号、无效标记、扫描后内容冲突及命令失败。
- 任一前置条件失败时不得执行第二阶段写入命令，也不得改变用户文件。

## 第八阶段：恢复中心

- 集中展示当前扫描中可安全恢复的项目，不要求操作历史仍然存在。
- 单独展示当前状态仍匹配的可撤销操作；失效、失败或已撤销记录只能作为历史查看。
- 恢复仍需二次确认并经过原控制器全部安全校验，恢复中心不得绕过来源、权限、指纹或状态检查。

## 第九阶段：资源观察

- 资源观察必须由用户主动触发，只对扫描结果中已有 PID 执行一次公开 `ps` 采样，不做持续轮询。
- 展示 CPU 百分比、常驻内存和运行时长，并明确采样时间；无 PID 或采样后进程退出时显示未知。
- 采样不写入扫描快照、操作历史或导出报告，避免把短期运行数据误认为稳定审计结论。

## 第十阶段：正式发布

- 发布只能从干净工作区开始，拒绝已存在的版本标签，并继续使用稳定 Nekutai 签名链路。
- 组装后检查应用结构、bundle id、最低系统版本、图标、可执行文件和非 ad-hoc 签名。
- DMG 创建后执行完整性验证并生成 SHA-256；GitHub Release 同时上传 DMG 与校验文件。
- 发布前的真实控制流程验收必须使用专用测试项目，不得拿用户的重要启动项做试验。

## 第十一阶段：管理员辅助程序

- 使用 `SMAppService.daemon(plistName:)` 注册应用包内的 LaunchDaemon，由管理员在系统设置中明确批准。
- 主应用使用 privileged Mach service 连接；主应用和辅助程序都必须在恢复 XPC 前通过固定标识与 Nekutai 证书要求验证对端。
- 辅助程序必须以 root 身份运行才接受连接，协议版本不匹配时主应用拒绝继续。
- 第一功能点只开放无副作用的连通性检查；任何全局启动项操作必须在后续窄接口中逐项加入和验收。

## 第十二阶段：全局 LaunchAgent 控制

- 只管理 `/Library/LaunchAgents` 中 root 拥有的普通 plist，并只影响发起请求用户的 `gui/<uid>` 域。
- 主应用传递扫描时 SHA-256；辅助程序重新读取并校验路径无符号链接、完整文件指纹、Label、绝对执行路径和非 Apple 签名。
- 辅助程序只执行固定参数数组的 `/bin/launchctl disable/enable` 与 `bootout/bootstrap`，不接收任意命令、参数数组或 shell 文本。
- 任一验证失败时不得调用 launchctl；停用和恢复都不删除或改写 plist。

## 第十三阶段：LaunchDaemon 控制

- 只管理 `/Library/LaunchDaemons` 中 root 拥有的普通 plist，并固定使用 launchd `system` 域；操作影响整个系统，确认文案必须明确说明。
- 沿用全局 Agent 的路径、符号链接、文件指纹、Label、绝对执行路径和 Apple 签名校验，任一失败不得调用 launchctl。
- XPC 接口只接收 path、label、扫描指纹和目标开关；辅助程序自行构造固定的 `system/<label>` 与 `bootout/bootstrap` 参数。
- 测试必须覆盖路径逃逸、符号链接、所有权错误、文件变化、危险 Label、Apple 目标、命令失败和超时。

## 第十四阶段：可解释风险评级

- 风险等级只使用“低风险 / 需关注 / 高风险”，不展示无法解释的综合分数。
- 评级依据覆盖目标缺失、代码签名、启动域权限、Cron 与 Shell 隐蔽性、RunAtLoad、KeepAlive 和相较上次扫描新增。
- 列表显示等级，详情逐条显示原因；高风险提供独立筛选，但评级本身不得自动执行停用操作。

## 第十五阶段：冲突与残留检测

- 单独汇总执行目标缺失、跨来源重复 Label、重复执行文件、Homebrew 与 launchd 管理重叠及重复 Shell 命令。
- 发现项必须说明判断依据并关联回原启动项，不将启发式检测伪装成扫描错误，也不自动删除残留。
- 路径比较只使用扫描阶段已归一化的字段，不为检测额外探测受保护目录。

## 第十六阶段：审计时间线

- 将单次快照升级为最近 30 次滚动历史，兼容迁移旧版单快照文件；继续只保存脱敏标识和状态字段。
- 时间线合并首次发现、扫描中移除、状态变化与用户控制操作，并按发生时间倒序展示。
- 用户可选择任意两个保留的扫描点，查看新增、移除和状态变化数量；比较不触发新的文件探测。
